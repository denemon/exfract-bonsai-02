# Integrated editable study — integrated-v03

This stage is an actual Three.js/WebGL scene and a self-contained editable bonsai model. It is **not a finished premium garden**. Read `REPORT.md`, `models/selection.json` and `INDEPENDENT-REVIEW.md` before extending it. The protected v23 runtime candidate and the stage-four accepted coarse cage remain unchanged.

- Local production preview: http://127.0.0.1:5192/ . Text-free scene only. Pointer drag turns slightly; wheel/pinch approaches; double click resets. Reduced motion suppresses camera gestures. No idle render loop.
- `site/`: source with pinned Three 0.185.1 and Vite 8.2.2. It resolves the already installed root dependencies. `npm run build` builds locally; `npm run preview` runs only on localhost 5192. `npm run dev` uses 5191 when free. The build shares public models/decoder/stills through local symlinks to avoid duplicate data; it is not a portable publishing archive. No deployment was made.
- `models/integrated-v03.blend`: 2,314 editable wood controls / 2,312 faces; unapplied Catmull–Clark level 1; connected trunk and five main branches; named editing groups; one continuous living/dead surface mask. Leaves, twigs, pot, substrate and stone are present. Twelve hidden LOD prototypes remain for export. Save future edits to a new file. Native geometry is self-contained; the browser is the lighting/material source of truth.
- `models/form-v08.json` is the exact selected wood record. `form-v01.json` through `form-v10.json` retain the other construction states. All ten were recreated in Blender and checked for matching evaluated counts/volume, closed single component and no detected nonadjacent intersections. The v09/v10 trials are rejected visual evidence, not improvements to apply.
- `models/integrated-v03.glb`: selected compressed runtime mesh, GPU foliage instances and extras. `models/integrated-v03.canopy-topology.json` stores branch/twig and shoot attachments. `sculpt/integrate.py` can restore a control record and regenerate the canopy into a **new version** using `--base form-v08 --version NEW_NAME --canopy-controls sculpt/canopy-v02.controls.json --native`. Existing output names are protected by an assertion. Procedural regeneration reproduces these stored controls, not later manual edits.
- `sculpt/form.py`, `planes.py`, `facets.py`, `spalls.py` are the actual construction experiments. `spalls.py` and form-v09 are rejected directions. `sculpt/verify_restore.py` checks the compact records in memory. `finish_native.py` and `fix_model_metadata.py` document the selected export's finishing/provenance operation; they are not intended to be blindly rerun over later edits.
- `site/public/still-manifest.json` links four WebP fallback views and HTML thumbnails to exact same-scene Mac screenshots and model SHA. No generated image is the runtime backdrop. `site/scripts/prepare_delivery.py` regenerates these static fallbacks from the retained screenshots. Update all stills after a future visual edit.
- `qa/final-production/` contains actual production-build screenshots and 44 functional checks. `qa/final-performance/` contains actual GPU timer queries. `comparison.html` distinguishes selected/rejected diagnostic clay from production views. 390px/320px are Mac Chrome viewport emulations, not physical-phone tests.
- QA scripts require `QA_PROFILE` pointing to `../local-structure-2122/qa/browser-profile` at the runs level, acquire its adjacent `.active` lock, and must not run concurrently. No new profile was made and the 55 old profiles are not approved for deletion. `capture.mjs` supports `QA_SCREENSHOTS=0` for metric-only measurements.

No Git write, push/PR/merge, publication, purchase, new ZIP, old-project change or Library retry. Library file IDs are unavailable because the earlier official helper failed TLS initialization. The original 302×404 attachment was inspected as visible pixels; its original bytes were not obtained locally.
